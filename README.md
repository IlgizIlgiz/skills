# Инструкции по установке навыков (Skills) для AI Ассистентов

Этот репозиторий содержит полезные навыки (skills) для расширения возможностей AI-ассистентов: **Claude Code**, **Cursor (Codex)** и **Gemini CLI**.

На данный момент доступны три основных навыка:
1. **Deep Planning** — система глубокой декомпозиции задач с поддержкой параллельных планов.
2. **Journal** — единая система ведения журнала работ.
3. **Docs** — организация документации CLAUDE.md: разбивка на ядро + файлы в docs/.

---

## 1. Deep Planning Skill

Система глубокой декомпозиции задач, позволяющая AI-ассистентам разбивать сложные задачи на шаги и выполнять их последовательно.

### Возможности:
- **Селектор сложности** для новых задач.
- **Глубокая декомпозиция** на задачи, подзадачи и шаги.
- **Поддержка параллельных планов** (каждый план хранится в отдельной изолированной папке).
- **Проверка конфликтов** по `Affected Files`.
- **Пошаговое выполнение** (команда `dp-next`) и мониторинг прогресса (`dp-status`).
- **Автоматическое завершение** с сохранением отчёта в Журнал (`journal/YYYY-MM-DD/`).

---

## 2. Journal Skill

Единая система ведения журнала работ. Может использоваться как самостоятельно (для ручной записи), так и в связке с Deep Planning (автоматическая запись по завершению плана).

### Возможности:
- **Ручная запись (`/journal`):** команда анализирует `git log`, определяет незаписанные изменения и создаёт понятный отчёт.
- **Автоматическая запись:** интеграция с Deep Planning для автоматического сохранения отчётов после выполнения задач.
- **Дедупликация:** проверка существующих записей во избежание дублей (скил не запишет то, что уже сохранил Deep Planning).
- **Простой язык:** отчёты пишутся понятным языком, удобным для нетехнических специалистов и руководителей. Одна логическая задача = один файл.

---

## 3. Docs Skill

Скилл для организации документации проекта. Разбивает CLAUDE.md на компактное ядро с тегами + подробные файлы в `docs/`.

### Возможности:
- **Первый запуск** — анализирует CLAUDE.md, разделяет на ядро (в тегах `ESSENTIAL:START/END`) + детальные файлы в `docs/`, верифицирует по коду.
- **Повторный запуск** — проверяет актуальность документации, обновляет только расхождения с кодом, не трогает блок без причины.
- **Верификация** — проверяет файловую структуру, зависимости, команды, CI/CD на соответствие документации. Спрашивает пользователя при неопределённостях.
- **Безопасность** — предупреждает о секретах в документации.

### Результат:
```markdown
# Проект
<!-- DOCS: При изменении документации используй /docs -->
<!-- ESSENTIAL:START -->
[Компактное ядро — стек, сервер, деплой, команды]
<!-- ESSENTIAL:END -->

## Подробная документация
- [Web](docs/web.md) — ...
- [API](docs/api.md) — ...
```

## Инструкции по установке

### 🔧 Установка для Claude Code

**1. Journal Skill:**
- В корне вашего проекта создайте директорию для команд: `mkdir -p .claude/commands`
- Создайте файл `.claude/commands/journal.md` и скопируйте в него текст промпта для Journal.
- Создайте папку для хранения отчётов: `mkdir -p journal` (её можно добавить в `.gitignore`, если вы не хотите хранить историю в репозитории).

**2. Deep Planning Skill:**
- Основные файлы команд (например, `deep-plan.md`, `dp-next.md`, `dp-status.md`) поместите в папку `.claude/commands/`.
- *Интеграция с Journal:* В файле `dp-next.md` (в шаге "Save to History") измените путь сохранения отчётов с `deep-planning-skill/history/YYYY-MM-DD/` на `journal/YYYY-MM-DD/`.

**3. Docs Skill:**
- Скопируйте файл `docs skill/commands/docs.md` в `.claude/commands/docs.md` вашего проекта.
- Запустите `/docs` — скилл автоматически разберёт CLAUDE.md на ядро + файлы в `docs/`.

---

### 🔧 Установка для Cursor / Codex

В Codex этот рабочий процесс устанавливается как дефолтный skill.

**Шаги установки:**
1. Поместите файлы навыка `deep-planning` в глобальную директорию: `~/.codex/skills/deep-planning`.
2. Убедитесь, что в файле `~/.codex/skills/deep-planning/SKILL.md` настроено хранение планов в локальной папке проекта `deep-planning-skill/<plan-id>/` (вместо устаревшего пути `doc/plans`).
3. Проверьте глобальный файл инструкций `~/.codex/AGENTS.md`. Блок про глубокое планирование должен ссылаться на `deep-planning-skill/<plan-id>/STATUS.md`.
4. Если в вашем проекте есть локальный `AGENTS.md`, убедитесь, что он не переопределяет пути обратно на `doc/plans`.

**Быстрая проверка после установки:**
```bash
rg -n "doc/plans|deep-planning-skill" ~/.codex/AGENTS.md ~/.codex/skills/deep-planning
```
*Ожидаемый результат:* Упоминаний `doc/plans` быть не должно, везде должен использоваться путь `deep-planning-skill/`.

### 🔧 Установка для Gemini CLI

Gemini CLI поддерживает подключение навыков через глобальную директорию или локально в проекте.

**Шаги установки:**
1. **Глобальная установка:** Поместите директорию с навыком в папку `~/.gemini/skills/` (например, `~/.gemini/skills/deep-planning`).
   - Основной файл с инструкциями навыка внутри папки должен называться `SKILL.md`.
2. **Локальная установка:** Вы также можете разместить файл навыка с расширением `.skill` прямо в корне вашего проекта (например, `deep-planning.skill`).
3. При запуске Gemini CLI автоматически обнаружит доступные навыки. Для активации нужного навыка в процессе работы AI-агент использует встроенный инструмент (например, `activate_skill { name: 'deep-planning' }`).

## Формат записей Журнала (Пример)

Структура папок в проекте:
```text
journal/
└── 2026-03-19/
    ├── 001-account-redesign.md   ← создано автоматически через deep-plan
    └── 002-fix-auth-bug.md       ← создано вручную через /journal
```

Пример содержимого файла отчёта:
```markdown
# Настройка авторизации через Telegram

## Summary
Реализован вход пользователей через Telegram-бота, исправлены ошибки с сессиями.

## Completed
2026-03-19

## Files changed
- src/controllers/auth.ts
- frontend/src/components/Login.tsx

## What was done
- Добавлена кнопка входа через Telegram на главную страницу.
- Настроен бэкенд для валидации данных от Telegram.
```
