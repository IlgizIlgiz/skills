# Journal Skill for Claude Code

Единая система ведения журнала работ. Используется как самостоятельно (`/journal`), так и автоматически при завершении deep-plan.

## Что умеет

- **Ручная запись** — `/journal` анализирует git log, определяет что ещё не записано, создаёт записи
- **Автоматическая запись** — deep-plan при завершении плана сохраняет отчёт в тот же журнал
- **Дедупликация** — `/journal` проверяет существующие записи и не дублирует то, что уже записал deep-plan
- **Простой язык** — пишет для руководителя без технического образования
- **Одна задача = один файл** — удобно просматривать и фильтровать

## Установка

### 1. Создать команду в проекте

```bash
mkdir -p <project>/.claude/commands
```

Создать файл `<project>/.claude/commands/journal.md`:

```markdown
Добавь отчёт о проделанной работе в журнал.

## Действия:

1. Определи сегодняшнюю дату (формат YYYY-MM-DD)
2. Проверь существующие файлы в `journal/YYYY-MM-DD/` — прочитай все `.md` файлы если есть
3. Проанализируй git log за сегодня: `git log --since="today 00:00" --oneline`
4. Определи какие коммиты ещё НЕ отражены в существующих записях журнала
5. Если всё уже записано — сообщи "Журнал актуален, новых задач нет"
6. Сгруппируй новую работу по логическим задачам и создай файл(ы)

## Структура:

journal/
  YYYY-MM-DD/
    001-account-redesign.md    ← создаётся deep-plan при завершении
    002-fix-auth-bug.md        ← создаётся /journal для ручной работы

## Формат файла (единый с deep-plan):

# [Понятное название задачи]

## Summary
[1-3 предложения что сделано — простым языком для руководителя]

## Completed
[YYYY-MM-DD]

## Files changed
- path/to/file1.ts
- path/to/file2.ts

## What was done
- Описание что сделано понятным языком
- Ещё пункт если нужно

## Правила:

- Создай `journal/YYYY-MM-DD/` если папки нет: `mkdir -p journal/YYYY-MM-DD/`
- Нумерация файлов: проверь существующие файлы, следующий номер (001, 002, 003...)
- **Одна логическая задача = один файл**
- Не дублируй то, что уже записано в existing файлах (deep-plan мог уже записать)
- Пиши **простым языком** для руководителя без технического образования
- В "Files changed" — реальные пути файлов
- В "What was done" — НЕ упоминай названия функций/переменных, пиши по-человечески
- Если эта команда уже запускалась в текущей сессии — анализируй только работу ПОСЛЕ предыдущего запуска
```

### 2. Интеграция с deep-plan

Если используется deep-plan, нужно обновить `dp-next.md` — в шаге 8b "Save to History" заменить путь:

**Было:**
```
deep-planning-skill/history/YYYY-MM-DD/NNN-<plan-kebab-name>.md
```

**Стало:**
```
journal/YYYY-MM-DD/NNN-<plan-kebab-name>.md
```

Также заменить `mkdir -p deep-planning-skill/history/YYYY-MM-DD/` на `mkdir -p journal/YYYY-MM-DD/`.

В `deep-plan.md` заменить упоминание `HISTORY.md` на:
```
Note: Completed plan reports go to `journal/YYYY-MM-DD/` (handled by dp-next on completion).
```

### 3. Создать папку в проекте

```bash
mkdir -p <project>/journal
```

Рекомендуется добавить `journal/` в `.gitignore` если не хотите хранить в репозитории, или оставить — если хотите иметь историю работ в git.

## Использование

| Команда | Что делает |
|---|---|
| `/journal` | Записать в журнал работу за текущую сессию |

Deep-plan записывает автоматически при завершении плана — вызывать `/journal` для этого не нужно.

## Что создаётся в проекте

```
journal/
├── 2026-03-10/
│   ├── 001-gemini-key-management.md    ← от deep-plan
│   └── 002-fix-login-bug.md           ← от /journal
├── 2026-03-11/
│   └── 001-auth-refactor.md           ← от deep-plan
└── 2026-03-12/
    ├── 001-account-redesign.md         ← от deep-plan
    ├── 002-bot-avatar-fix.md           ← от /journal
    └── 003-landing-redirect.md         ← от /journal
```

## Формат записи (единый)

```markdown
# Понятное название задачи

## Summary
1-3 предложения что сделано простым языком.

## Completed
2026-03-12

## Files changed
- frontend/src/components/AccountContent.tsx
- backend/src/controllers/auth.controller.ts

## What was done
- Переделана страница аккаунта — убраны лишние поля
- Добавлена кнопка выхода из аккаунта
```

## Как работает

1. `/journal` вызывается пользователем в конце рабочей сессии
2. Скилл читает `git log --since="today 00:00"` для определения сделанной работы
3. Проверяет `journal/YYYY-MM-DD/` — что уже записано (deep-plan мог записать часть)
4. Группирует незаписанные коммиты по логическим задачам
5. Создаёт по файлу на каждую задачу с последовательной нумерацией
6. Если всё уже записано — сообщает "Журнал актуален"
